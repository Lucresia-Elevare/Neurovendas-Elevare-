# Métodos e Frameworks - Neurovendas-Elevare

Esta pasta contém metodologias, frameworks proprietários e processos de negócio da plataforma Neurovendas.

## 📁 Estrutura

### `/frameworks` - Frameworks Proprietários
Frameworks e metodologias exclusivas desenvolvidas pela Neurovendas.

**Tipos de conteúdo:**
- Framework de Neurovendas
- Metodologias de conversão
- Frameworks de autoridade digital
- Sistemas proprietários de vendas

**Exemplo:**
```

/frameworks/framework-conversao-high-ticket.md
/frameworks/metodo-autoridade-digital.md
```

**Tipos de conteúdo:**
- Processos de vendas
- Processos de onboarding de clientes
- Processos de suporte
- Processos internos
- SOPs (Standard Operating Procedures)

**Exemplo:**
```
/processes/processo-vendas-consultiva.md
/processes/onboarding-cliente-premium.md
/processes/sop-atendimento-suporte.md
```

Fluxos de trabalho automatizados e integrações.

**Tipos de conteúdo:**

**Exemplo:**

## 🎯 Boas Práticas

### Para Frameworks
1. **Seja Claro e Objetivo**
   - Use linguagem acessível
   - Evite jargões desnecessários
   - Forneça exemplos práticos

2. **Estruture Bem**
   - Divida em componentes claros
   - Use hierarquia visual
   - Inclua diagramas quando possível

3. **Valide com Dados**
   - Inclua casos de sucesso
   - Mostre resultados esperados
   - Documente métricas

### Para Processos
1. **Detalhe Responsabilidades**
   - Defina quem faz o quê
   - Estabeleça prazos
   - Determine aprovadores

2. **Seja Sequencial**
   - Ordem lógica de execução
   - Dependências claras
   - Pontos de decisão marcados

3. **Inclua Exceções**
   - Fluxos alternativos
   - Tratamento de erros
   - Escalação

### Para Workflows
1. **Documente Integrações**
   - Sistemas envolvidos
   - APIs utilizadas
   - Credenciais necessárias (sem expor secrets)

2. **Automatize Quando Possível**
   - Reduza intervenção manual
   - Use ferramentas apropriadas
   - Monitore execuções

3. **Prepare para Falhas**
   - Retry logic
   - Notificações de erro
   - Rollback quando necessário

## 🔄 Versionamento

### Quando criar nova versão:
- Mudanças significativas na metodologia
- Novos componentes ou etapas
- Mudanças em KPIs ou métricas
- Otimizações importantes

### Como versionar:
```
meu-metodo-v1.md  → Versão inicial
meu-metodo-v2.md  → Versão atualizada (breaking changes)
meu-metodo-v1.1.md → Versão minor (melhorias)
```

## 🚀 Como Contribuir

1. **Identifique a categoria** (framework, processo ou workflow)
2. **Use o template apropriado**
3. **Documente detalhadamente**
4. **Inclua exemplos reais**
5. **Valide com stakeholders**
6. **Submeta via Pull Request**
